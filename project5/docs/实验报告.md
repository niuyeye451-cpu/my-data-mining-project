## 二、实验原理

### 2.1 倒排索引（Inverted Index）

传统关系型数据库使用正排索引（逐行扫描），查询"包含'螺丝'的商品"需要执行 `LIKE '%螺丝%'` 的全表扫描。搜索引擎采用**倒排索引**：预先将每个词（Term）映射到包含它的文档 ID 列表。

```
倒排索引结构：
  "螺丝"   → [doc1, doc5, doc8, doc12, ...]    ← Posting List
  "不锈钢" → [doc2, doc5, doc9, doc15, ...]
  "轴承"   → [doc3, doc7, doc11, ...]
```

查询时将多个词的 Posting List 取交集（AND）或并集（OR），时间复杂度为 **O(词项数)**，远优于全表扫描的 O(文档数)。

### 2.2 中文分词（IK Analyzer）

英文以空格分词，中文需要专门的**词典+规则分词器**。IK Analyzer 提供两种模式：

| 模式 | 策略 | 示例："高强度不锈钢螺丝" | 用途 |
|---|---|---|---|
| **ik_max_word** | 最细粒度穷举 | `[高强度, 高, 强度, 不锈钢, 不锈, 钢, 螺丝, 螺, 丝]` | **索引时**：最大化召回率 |
| **ik_smart** | 最粗粒度最少切分 | `[高强度, 不锈钢, 螺丝]` | **搜索时**：提升精准度 |

关键设计：「索引时细粒度 + 搜索时粗粒度」。搜"不锈钢螺丝"能命中所有含不锈钢或螺丝的商品（ik_max_word 索引），但不会误匹配"不锈铁"之类（ik_smart 搜索）。

### 2.3 Bool 查询（Boolean Query）

ES 的核心查询模式，将搜索条件分为两类上下文：

| 上下文 | 作用 | 评分 | 缓存 | 本实验用途 |
|---|---|---|---|---|
| **must** | 必须匹配，影响相关性分数 `_score` | ✅ 参与 BM25 计分 | ❌ | 关键词全文搜索 `title` |
| **filter** | 必须满足，不影响分数 | ❌ 二分判断 | ✅ ES 自动缓存 | 类别/地区/VIP/价格区间 |

```json
{
  "query": {
    "bool": {
      "must":   [{ "match": { "title": "螺丝" }}],          // 全文匹配，影响评分
      "filter": [
        { "term": { "parentid": 22 }},                       // 地区=重庆
        { "term": { "vip": 1 }}                              // 只看VIP
      ]
    }
  }
}
```

`filter` 结果被 ES 自动缓存（BitSet），后续相同过滤条件直接命中缓存，第二查询比首次快 10-100 倍。

### 3.3 数据库表设计

用 `init_data.sql` 建库建表，共 7 张表。**gyy_mall 是搜索引擎的源数据表**：

```sql
CREATE TABLE gyy_mall (
    itemid    INT PRIMARY KEY AUTO_INCREMENT,
    title     VARCHAR(500) NOT NULL,       -- ★ 全文搜索目标字段
    price     FLOAT DEFAULT 0,              -- 价格（排序+区间过滤）
    picture   VARCHAR(500) DEFAULT '',
    catid     INT DEFAULT 0,               -- FK → gyy_category

    areaid    INT DEFAULT 0,               -- FK → gyy_area

    parentid  INT DEFAULT 0,               -- 省级ID，搜索过滤关键字段
    vip       INT DEFAULT 0                -- 0=普通 1=VIP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

数据量：area(36) + category(33) + company(200) + mall(500) + user(2)

### 3.6 搜索查询构建（search.py，核心）

```python
async def search_products(es, params, index):
    must   = []   # ★ 全文搜索，参与评分
    filter = []   # ★ 精确过滤，不评分，ES缓存

    if params.q.strip():
        must.append({"match": {"title": params.q}})       # 关键词 → must
    else:
        must.append({"match_all": {}})

    if params.areaid > 0:
        filter.append({"term": {"parentid": params.areaid}})  # 地区 → filter
    if params.catid > 0:
        filter.append({"term": {"catid": params.catid}})      # 类别 → filter
    if params.vip == 1:
        filter.append({"term": {"vip": 1}})                   # VIP → filter
    if params.price_min or params.price_max:
        filter.append({"range": {"price": {"gte": ..., "lte": ...}}})  # 价格 → filter

    body = {
        "query":   {"bool": {"must": must, "filter": filter}},
        "from":    (params.page - 1) * params.size,
        "size":    params.size,
        "highlight": {"fields": {"title": {}},               # ★ 关键词高亮
                      "pre_tags": ["<mark>"], "post_tags": ["</mark>"]},
        "aggs": {                                            # ★ 聚合计数
            "cat_counts":  {"terms": {"field": "catid", "size": 35}},
            "area_counts": {"terms": {"field": "parentid", "size": 40}}
        }
    }
    if params.sort == "asc":   body["sort"] = [{"price": "asc"}]
    if params.sort == "desc":  body["sort"] = [{"price": "desc"}]

    resp = await es.search(index=index, body=body)
    return parse_results(resp)
```

## 五、实验分析与总结

### 5.1 成果

本实验完整实现了工业商品中文搜索引擎，具备以下能力：

- **ES 索引**：IK 分词双模式（索引时 ik_max_word + 搜索时 ik_smart），bool 查询（must + filter）
- **多条件筛选**：关键词搜索 + 33类 + 36地区 + VIP + 价格区间，5 种过滤维度自由组合
- **用户体验**：关键词高亮 `<mark>`、标签实时计数、筛选芯片可视化、URL 可收藏
- **部署**：`docker compose up -d` 一键启动 MySQL + ES
- **代码量**：~500 行 Python + ~500 行 HTML/JS，结构清晰

### 5.2 遇到的问题与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| IK 插件安装 HTTP 404 | GitHub 仓库迁移至 infiniLabs | 改用 `get.infini.cloud/elasticsearch/analysis-ik/8.17.0` |
| 表单提交 HTTP 422 | 空 `price_min=&price_max=` 无法解析为 float | 参数类型改为 `str`，`_parse_float()` 空→None |
| ES 镜像 662MB 下载慢 | 需翻墙或 CDN 限速 | 后台 `docker compose up -d`，不影响开发 |
| Playwright 版本不匹配 | chromium-1217 vs 需要 -1223 | symlink 映射解决截图工具链 |

### 5.3 改进方向

1. **搜索建议/纠错**：ES `suggest` + `fuzzy` 实现"螺丝"→纠正"罗丝"等输入错误
2. **公司关联推荐**：复用 `gyy_company_reset` 表，搜索时用 `reSort` 逻辑推荐关联公司商品
3. **用户认证落地**：前端表单已就绪，后端需接 MySQL 实现真实注册登录 + Session
4. **聚合面板**：侧边栏已有计数，可加"价格分布直方图"
5. **大数据量测试**：当前 500 条，可扩展到百万级测试 ES 集群性能
